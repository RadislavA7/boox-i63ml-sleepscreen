# Как это работает

Заметки по прошивке Onyx Boox i63ML Newton (`I63MLP_HD`, `e346d7e`, Android 2.3.1, Rockchip RK29). Всё получено дизассемблированием системных библиотек и экспериментами на самой книге.

## 1. Откуда система берёт картинку сна

В SurfaceFlinger (`libsurfaceflinger.so`) при выключении экрана вызывается цепочка `turnElectronBeamOff → showAdvt(mode) → initLogo(mode)`; `mode` = 1 (сон), 2 (выключение, если `ro.shutdown.with.picture=1`), 3 («нет питания»). `initLogo` сначала пробует декодировать файл **`/data/misc/advt.png`** (для любого режима). Если декодировать не вышло, берутся штатные картинки из `/system/framework/framework-res.apk`: `images/standby-custom0..4.png` по кругу (их число задаёт `ro.standby.image.num`, у книги 5), `images/shutdown.png`, `images/nopower.png`.

Картинка рисуется в framebuffer 1024×758 **без поворота**, а интерфейс книги повёрнут (`ro.sf.hwrotation=90`). Поэтому «правильная» заставка в портретной ориентации 758×1024 должна быть **повёрнута на 90° по часовой стрелке** и сохранена как PNG 1024×758, 8 бит RGB. После рисования SurfaceFlinger вызывает `requestEpdMode(8)` и `flip`.

## 2. Ссылка вместо подмены файла

`/data/misc` пишется только root'ом. Чтобы не просить root при каждой смене картинки, приложение хранит настоящий файл в своём каталоге (`files/advt.png`, права 644, запись атомарная: временный файл и `rename`), а root один раз создаёт символическую ссылку `/data/misc/advt.png → …/files/advt.png`. Дальше смена заставки это обычная запись в свой файл. «Восстановить» удаляет целевой файл: SurfaceFlinger не может его декодировать и показывает штатные картинки.

## 3. Какая книга сейчас читается

Читалка (AlReader для Onyx) пишет историю в общую базу Onyx. Провайдер `content://com.onyx.android.sdk.OnyxCmsProvider/library_metadata` открыт без разрешений и присылает уведомления об изменениях. Приложение берёт книгу с наибольшим `LastAccess` (только файлы книг и только существующие), подписывается на изменения (`ContentObserver`), на включение/выключение экрана, на монтирование карты, на таймер раз в полчаса и на загрузку системы.

Обложка: из самого файла (`BookCovers`: FB2 `coverpage` → `binary`, EPUB `meta cover`/`cover-image`/`guide`, MOBI EXTH 201/202), иначе миниатюра Onyx (`library_thumbnail`), иначе карточка. Название и автор (`BookMeta`): метаданные книги, затем база Onyx, затем имя файла. Картинка обрабатывается в чистом Java: серый, автоконтраст, область вписывается на белом фоне или по краям, PNG кодируется собственным кодировщиком.

## 4. «Призрак» на заставке и очистка экрана

**Причина.** При нажатии кнопки питания система рисует заставку почти сразу «быстрым» режимом e-ink (режим 8) поверх прежней страницы, и контуры старого изображения остаются, особенно заметные на тёмной обложке.

**Что выяснено про e-ink.**
* Кадры идут в драйвер `/dev/ebc` (устройство открыто для всех, права 0777): `ioctl 0x7000` берёт свободный буфер кадров, `ioctl 0x7001` отправляет его с режимом обновления (`epd_mode`) и окном на экране. Режимы: 0 AUTO, 1 FULL, 2 A2, 3 PART, 5 **RESET** (мигание в белое без показа картинки), 8 «заставка», 10 OED_PART.
* Системное свойство `rk.epd.mode` (>0) принудительно задаёт режим кадра, но для заставки при засыпании этого мало: полосы остаются и при принудительном режиме 1.
* Лучший результат дало **«сброс (режим 5), потом заставка (режим 8)»**: на стенде из крупных вертикальных полос под тёмной обложкой полосы сильные → слабые.
* Системная команда «перерисовать»/«сбросить» (`EpdManager`, служба `epd`, `ioctl 0x6004/0x6005` на fb0) картинку не очищает и не возвращает.

**Как приложение успевает сбросить экран до заставки.** От нажатия кнопки питания до начала сна проходит около 580 мс (кнопка вниз → вверх ≈250 мс → ещё 300 мс до `mPowerSleep`). В системном журнале появляется запись `WindowManager: interceptKeyTq keycode=26 screenIsOn=true …` (при нажатии и при отпускании) и `jeffy: mPowerSleep` в момент засыпания. Приложение (`PowerKeyWatcher`, нужен `READ_LOGS`) читает `/dev/log/main`, по первой записи сразу шлёт кадр RESET через `/system/bin/ioctl` (`EbcReset`, ~50 мс), и система через полсекунды рисует заставку на уже очищенной панели. Нажатие, которое будит книгу, пропускается: у него первая запись приходит с `screenIsOn=false`.

**Страховка.** Если после сброса книга не заснула (например, держали кнопку и отменили меню выключения), через 2,2 с на 0,4 с добавляется прозрачное окно на весь экран, и система перерисовывает страницу (`ScreenRefresher`). Если система при этом считает экран выключенным, сброс вообще пропускается.

**Ограничение.** Когда книга засыпает по таймеру, нажатия кнопки нет и нечем «узнать заранее»: очистки в этом случае нет.

## 5. Предупреждение разработчикам: экранные wake lock'и

На этой прошивке нельзя из приложения держать **экранный** wake lock (`FULL_WAKE_LOCK`, особенно с `ACQUIRE_CAUSES_WAKEUP`) с таймаутом. Когда он истекает и экран должен погаснуть, `PowerManagerService` Onyx падает с `SecurityException … WRITE_SETTINGS` (проверка прав идёт от имени приложения), состояние питания остаётся «наполовину выключенным», и кнопка питания перестаёт будить книгу. Выручает перезагрузка. Частичные (`PARTIAL_WAKE_LOCK`) wake lock'и безопасны.

## 6. Что ещё полезно знать

* Инжектированные кнопки (`input keyevent 26`) книгу не усыпляют: политика окон игнорирует их.
* Список wake lock'ов в `/proc/wakelocks` не показывает длительность обновления панели; `EpdManager.isBusy()` всегда `false`.
* Если открыть приложение (`am start`) при «выключенной» книге, UI попадает на панель, хотя система считает экран выключенным. Для проверок лучше будить книгу кнопкой.
* Снимок экрана для отладки: `dd if=/dev/graphics/fb0 of=/sdcard/fb0.bin bs=4096 count=1516` (читает shell без root); это две страницы BGRA 1024×758, нужная повёрнута на 90°.
